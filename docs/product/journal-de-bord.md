# Journal de bord

Comment la réflexion a évolué. Le journal des décisions dit *ce qui* a été décidé ; ce journal raconte *le chemin*, y compris les idées abandonnées. Une entrée par étape marquante, la plus récente en bas.

---

### 18/11/2026 · De l'objet à l'usage
- **Point de départ** : « refaire un Corsair Xeneon Edge sur mon téléphone ». L'idée était un clone : températures, horloge, widgets.
- **Premier prototype** sur téléphone : horloge, minuteur focus, liste du jour. En le construisant, la vraie question apparaît : ce qui manque n'est pas une stat matérielle, c'est un repère pour la concentration et le temps qui passe.
- **Recentrage** : le produit devient un outil de concentration pour développeurs. Ajout de « Une seule chose » et « Idées pour plus tard ».
- **Changement de support** : la tablette remplace le téléphone (D1). Plus de place, 6 widgets.

### 18/11/2026 · Du gadget à l'outil de travail
- **Lien avec le quotidien de dev** : le daily et la réunion technique demandent de se souvenir de ce qu'on a fait. Idée : faire écrire le rapport là où le travail se fait, dans Claude Code (D6).
- **Sport** : la ligne Sport commence en saisie manuelle, puis lit directement l'agenda (D5).
- **Arbitrage** : températures abandonnées au profit de Spotify (D3). Moins de technique impressionnante, plus d'usage réel, une installation plus simple.

### 18/11/2026 · D'un outil perso à un projet
- **Architecture** : la page publiée sur claude.ai ne suffit plus (pas d'accès aux fichiers du PC). Choix d'une API .NET locale (D4).
- **Projet public** : dépôt GitHub, données fictives, config perso hors de git (D7).
- **Volet produit** : le projet devient aussi une vitrine de démarche PM. Rôles posés : je suis la PM, Claude Code le développeur.
- **Dernière idée de la soirée** : voir et autoriser les demandes de Claude Code sur la tablette, avec une mascotte qui réagit (D8).

### 24/11/2026 · Phase 0, la réalité des données
- **Les vrais fichiers contredisent le plan** : les sessions Claude Code ont rarement un nom choisi (D9), et la date d'un fichier ne dit pas si la session est active (D10). Le plan a été corrigé à partir de ce qu'on a observé, pas supposé.
- **.NET 10** plutôt que 8, pour la durée de support (D11).
- **Confidentialité dans git** : e-mail des commits remplacé par l'adresse noreply de GitHub, historique réécrit avant publication.
- **Méthode** : ajout de la roadmap, du backlog en user stories, des définitions *Ready* / *Done* et de ce journal de bord.
